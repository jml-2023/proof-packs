# How the author's runs were made, 30 October 2026

Every time below is UTC. The local routes ran on the author's Windows PC; the jobs were started from a Mac over ssh, and no model ran on the Mac.

## The machine

Windows 11 Pro (build 26300), an NVIDIA GeForce RTX 4090 with 24,564 MiB of memory (driver 610.88, power limit 480 W), an Intel Core i9-14900KS and 192 GB of memory. The machine has a second graphics card, which the meter doesn't measure. Its GPU jobs share one lock (`flock` on a lock file in WSL); holding it keeps the others off the card, and every local run below held it.

- **Answering, local:** Ollama 0.35.1, run as a second, temporary server with its own port and model folder, so the machine's own server and models were untouched. gpt-oss:20b (MXFP4, 13,793,441,566 bytes, digest `f38aa0c53da5…`) was served with four slots, a 16,384-token context and flash attention. For qwen3.8:27b (Q4_K_M, 17,741,872,154 bytes, digest `aaee06c39dcf…`) the server was restarted with one slot and a 10,240-token context, because a 27B model's cache for four 16,384-token slots would not fit beside its weights; the model then sat wholly in the card's memory. Requests went from the Mac through an ssh tunnel, so the local waits include that trip.
- **Listening, local:** faster-whisper 1.2.1 with Whisper large-v3 in float16, in WSL Ubuntu, from the Python environment the machine's own word check uses. The job was piped in over ssh, worked in a temporary folder that it deleted, and ran under the GPU lock.
- **Cloud:** OpenRouter with its default routing (no provider pinned) and usage accounting on, so each reply carries its cost and the company that served it.

## Energy

`energy.mjs` integrates the card's power over each run's window and takes the processor's energy from its running counter, then subtracts the idle draw of the 60 s before the window. The sampler ran on the PC and the answering jobs on the Mac, so their clocks differ: `--offset-ms 230` is the PC's clock minus the Mac's, the 99th percentile of 2,307 pairs of timestamps logged as the samples arrived (median 222 ms). The listening jobs ran in WSL on the PC: `--offset-ms 66` and `62` come from the job's own clock readings (`CLOCK` lines) for the first and second runs. An error of a second in either offset changes a run's energy by well under 1%.

## Scoring after the runs

- **Answering.** The first answer reader missed replies that put the letter in bold ("The answer is **(E)**"). `score-answers.mjs` now strips Markdown emphasis before reading, and re-scored every run from the last 300 characters of each reply that the run kept. First pass to now: gpt-oss:20b local 99 to 103, gpt-oss-20b cloud 97 to 105, Gemini 3.8 Flash 128 to 128, Qwen3.8-27B cloud 123 to 123, and qwen3.8:27b local 38 to 38 on the 42 and 84 to 84 on the 98. Each item keeps its first reading as `got_first_pass`.
- **Listening.** The normaliser was last changed after a one-narration cloud trial, before any local transcript existed (years read in pairs, some old spellings, compounds). It doesn't expand "Mr" or "Mrs", and doesn't know "behaviourist"; those cost the cloud and the local route 7 words each, and are left in.
